# 三摄 RGB-D 分批抓放：V7 稳定版与 V9 释放候选

本目录作为 V15 之后的推荐复现入口，默认运行经过完整网格验证的 **V7**，通过 `--variant v9` 显式选择加入保护性释放的 V9 候选。原 [V15 目录](../sensor_v15/README.md) 保留，用于复现早期结果。两个版本的冻结源码分别在 [`bundles/v7/`](bundles/v7/) 和 [`bundles/v9/`](bundles/v9/)，入口不会将尚未通过发布验证的后续 R4 改动混入其中。

这是**经典 RGB-D 几何视觉控制系统**，使用三摄图像与米制深度、实测关节和公开机器人几何，不加载、训练或修改 π0.5。正式回合连续执行，右臂保持初始安全姿态，左臂输出七关节加夹爪的 8D 目标。每批操作后重新观察和规划，场景内的盒子与饼干不会被重置。

## 1. 发布选择与已完成结果

V7 为默认版本的依据是完整的两尺寸、三档随机化验证，以及与 V9 的同种子比较。V9 在后一轮 2×10 上更好，但其 2×5 有少量退化，尚无证据说明它整体优于 V7。

下表来自已完成的 **27000–27019 配对网格**：每个种子覆盖两种尺寸、三档随机化，两版各 120 回合，无基础设施错误。这里的“完整”指原生成功且控制器完成释放、撤离后的视觉自检，两项指标必须分开看。

## 2. 定位如何实现

### 2.1 三摄、深度和机器人坐标

正面相机提供全局盒体与排列信息，左腕相机随操作臂移动，补看抓取入口、持物及目标区域，右腕相机在固定右臂姿态下提供额外视角。使用原三个相机安装位置的 768×768 RGB-D；深度是相对纯 RGB 策略增加的传感信息。三路并非始终全部有效，未通过标定的视角不会以未知安装关系参与深度融合。

对有效像素及其米制深度，先按内参反投影，再变换到机器人基座坐标：

```text
p_camera = z · inverse(K) · [u+0.5, v+0.5, 1]
p_base   = R_base_camera · p_camera + t_base_camera
T_base_camera(q) = T_base_end_effector(q) · T_end_effector_camera
```

腕部移动后，由**实测关节**与公开机器人模型计算当前末端位姿，再更新腕相机外参。不会从仿真物体状态中取得盒子或饼干的位置。

### 2.2 开头的移动用于手眼标定

系统先根据 RGB-D 粗定位可见的源盒矩形盒沿，再让左腕在安全高度实际移动、停稳，从不同俯仰和侧倾姿态观察同一个静止盒沿。盒沿尺寸是公开先验，盒子随机化后的位姿由图像估计。

配对的机器人末端位姿与盒沿视觉变换用于 OpenCV Park 手眼求解，至少需要五个有效视角及足够的旋转多样性，并结合已知矩形尺寸检查焦距尺度。拟合、留出视角、法向及安装变化检查通过后才接受结果。V7 还区分“名义安装本已准确、再次拟合略差”与真正标定失败：只有通过独立验证及原绝对残差限制的名义候选才能保留。四边观测不足时允许一次有界左腕补拍，全部动作计入原回合预算。

左腕标定后的盒沿测量用于锚定其他能看清同一盒沿的相机。2 mm 拟合和 3 mm 留出等数值是接受阈值，不能写成已证实的系统绝对定位精度。平面测量补充高度与法向约束，不能单靠一个平面确定水平平移和偏航。

### 2.3 先拟合盒子，再检测可见薄片

深度反投影为点云后，在颜色和高度区间内提取盒沿，结合已知矩形尺寸估计源盒、目标盒的中心、方向和盒沿高度。普通定位需要足够的可见边支持；不同相机的完整盒体估计若明显冲突，会触发拒绝和补看。各相机可以分别支持不同盒体，单个腕部画面无需包含两个完整盒子。

饼干检测在视觉得到的盒坐标中进行，依据可见表面的颜色差异、高度、宽度、覆盖和起伏筛选薄片。源区横向位置受已知列排列约束，排列方向位置和顶部高度来自当前深度，方向沿用盒体与基本直立假设。目标区则检查可见顶面的位置与几何。相机内先形成完整实例，再跨视角匹配、去重和补充；没有看到的饼干不会仅凭排列先验生成。

这套方法面向已知尺寸、规则排列与基本直立的薄片，不能当作未知散乱物体的通用六自由度定位器。

### 2.4 空位需要正向证据

“没检测到饼干”不足以证明可以放置。系统在源区进入通道和目标槽位采样盒底点，将其投影到有效深度图；量到的深度与预期盒底吻合，才形成空闲证据。入口与目标区域仍使用原 90% 采样覆盖要求。被手臂遮挡、无效深度、越界和未知区域不能计为空位，90% 也不是定位准确率或成功概率。

目标槽位来自公开任务几何，通过**视觉测出的盒位姿**转换到机器人坐标。公开尺寸与槽位先验是方法的一部分，不能将“未输入物体真值”理解为没有几何先验。

## 3. 依次观察与场景记忆

抓取时无需同时看见源饼干和目标空位。早期实时检查容易在“看源区时目标被挡、看目标时源区被挡”之间来回切换。V7 继承的主动观察与场景记忆让两侧分别记录和补看，再将当前观测与有效历史证据联合用于准备动作。

1. 每批先停稳，用真实新图像和实测关节记录可见区域，同时保存原始采集时间、内外参和视觉盒体估计。
2. 源入口与目标空位分别检查；一边不充分，不会阻止另一边的有效记录。
3. 缺哪一侧，就实际移动左腕补看该侧。重复时间的缓存包不算新观测，旧帧也不改成当前时间。
4. 历史只用于本批准备阶段的有效可见性和空闲证据。**待抓五块的位置必须来自当前视觉**，释放结果和此前成果也必须用当前图像复核。
5. 操作开始和下一批准备时清理对应旧记录。历史上限为 12 个视角、15 秒，并检查盒位姿变化、区域变化和新障碍；盒体匹配要求为 2 mm、1°，发现冲突的旧空位证据会失效。

因此记忆保存的是带时间和几何来源的真实观察，不是固定轨迹，也不保证此前空位永远不变。右臂不主动移动；补看由左臂和原三摄完成。

## 4. 抓放闭环与相对 V15 的改动

正常流程为：

```text
标定 → 观察与记录 → 选择当前五块 → 接近、下探、夹持、提起
     → 持物测量 → 放置规划 → 搬运、预插入、插入
     → 释放、撤离 → 本批与此前成果验证 → 下一批重新观察
     → 最后一批完成后持续稳定确认
```

| 环节 | V7 默认行为 | 解决的共性问题 |
| --- | --- | --- |
| 观察 | 两侧独立调度、停稳记录、受约束历史复用 | 视角切换后丢失此前已看清的有效信息 |
| 标定 | 观测不足时有界补拍；准确名义候选需独立认证 | 遮挡与拟合噪声引发误拒 |
| 持物与放置 | 抬起后测量五块相对夹爪的实际偏移，再检查完整路径 | 抓取后的实际形态与计划不一致，末端目标难以精确执行 |
| 执行裕度 | 原姿态有足够裕度时保留，否则比较受约束姿态候选 | 数学上刚好可达、实际执行容易停滞 |
| 完成 | 新鲜图像、开度和编码器共同支持最终稳定确认 | 物体数量已满、物理状态尚未稳定就提前结束 |

放置规划检查搬运、预插入与最终落位的连续离散路径，并检查持物体积与盒壁、盒底、相邻排约束。候选包含原姿态及受约束的小角度变化；实际选择由当前测量及机器人可达性决定，不按种子指定偏移。默认姿态的高精度裕度不足时继续比较候选，而不是一旦勉强满足硬容差就提前返回。

每步左臂关节目标变化仍有界；原生接口需要 16D 时拼接回合初始安全右臂目标，右臂闲置不等于发送全零关节位置。下一批重新建立局部目标和观测状态，不能消除已经发生的碰歪或接触误差。

### V9 可选：窄开松夹，抬离后再充分张开

选择 `--variant v9` 时，入口启用 V9 冻结包的 `--guarded-release`：根据当前夹爪编码器和公开几何，只增加 2 mm 总间隙，经三个独立编码器时刻确认后保持窄开度抬离。实测 FK 确认指垫及未来完全张开的垂向扫掠端点都高于观测保护高度后，再继续撤离并充分张开。

保护高度来自盒沿、已观测旧物以及本批持物测量和刚性握持预测。它减少完全张开阶段的扫掠风险，但不等于实时接触证明。配对网格支持 V9 在部分 2×10 场景有改善，同时出现 2×5 退化，故本次保留为显式候选。

## 5. Linux 复现

需要 Python 3.12、可用的 MuJoCo EGL 驱动和冻结包的数值/渲染依赖，不需要模型权重或示范数据集。运行时另用一个干净的固定模拟器 checkout，**不能把本分支 HEAD 当作固定模拟器**。

### 5.1 下载与准备

```bash
git clone --branch codex/v15-rgbd-localization --single-branch \
  https://github.com/Eter0109/a3_dual_arm_sim.git a3-rgbd
cd a3-rgbd
export A3_RGBD_DIR="$PWD/examples/sensor_rgbd"
export A3_RGBD_WORK="$HOME/a3-rgbd-work"
export JOB="$A3_RGBD_WORK/job"
export SIM="$A3_RGBD_WORK/simulator"
mkdir -p "$A3_RGBD_WORK"

git clone https://github.com/Eter0109/a3_dual_arm_sim.git "$SIM"
git -C "$SIM" checkout 29fe90e423259f388ebc061926c3ec860b9edc74

python3.12 -m venv "$A3_RGBD_WORK/venv"
source "$A3_RGBD_WORK/venv/bin/activate"
python -m pip install --upgrade pip
python -m pip install -r "$A3_RGBD_DIR/bundles/v7/requirements-tested.txt"
python -m pip install -e "$SIM"

python "$A3_RGBD_DIR/bundles/v7/prepare_workspace.py" \
  --job "$JOB" --main-repo "$SIM"
source "$JOB/repro_env.sh"
```

准备工具检查固定提交和已跟踪文件的干净状态，链接模拟器并放置小型配置与确定性辅助代码；几何控制无需提供 checkpoint 或 tokenizer 参数。不要复用其他版本、参数不同且已有产物的工作目录。`.75` 是本仿真桌面高度，不能直接当作真实硬件标定结果。

冻结包可分别运行其测试：

```bash
export A3_TEST_BUNDLE="$A3_RGBD_DIR/bundles/v7"
PYTHONPATH="$A3_TEST_BUNDLE/code:$A3_TEST_BUNDLE/code/vendor:$SIM/src" \
  python -m unittest discover -s "$A3_TEST_BUNDLE/tests" -v
# 检查V9时，将A3_TEST_BUNDLE改为 "$A3_RGBD_DIR/bundles/v9"。
```

### 5.2 单回合与完整网格

先检查一个完整回合：

```bash
python "$A3_RGBD_DIR/run_grid.py" \
  --job "$JOB" --output "$A3_RGBD_WORK/outputs/v7_smoke" \
  --tasks 2x5 --profiles medium --episodes 1 --seed-start 28000 --workers 1
```

默认 `--variant v7`。入口固定开启原实验的手眼标定、`.75` 桌面高度、精细控制、场景记忆和完整放置规划；V9 额外开启保护性释放。准备和观察时间均计入预算。

完整六格网格，每格 20 回合，共 120 回合：

```bash

```

28000 为新运行命令示例，历史得分对应第一节明确列出的种子。比较时两版使用相同种子、预算、依赖和渲染配置，并保留全部失败。每个输出目录必须唯一；中断后用**同版本、同参数、同路径**增加 `--resume` 续跑。已有活动进程时不要重复启动。

```bash
python "$A3_RGBD_DIR/run_grid.py" \
  --job "$JOB" --output "$A3_RGBD_WORK/outputs/v7_grid_s28000" \
```

并行数按实际 CPU、内存与渲染显存调整，从一个回合开始核对资源，再增加工作进程。主要产物为 `status.json`、`report.json`、`summary.md`、`results.jsonl` 与逐回合 `cases/`；保存有限标定样本、日志和失败证据，不保存全量物理快照或模型。不同驱动、硬件和环境下不保证逐帧完全一致。

## 6. 固定研究协议与信息边界

| 项目 | 本次发布对应的设置 |
| --- | --- |
| 模拟器 | `29fe90e423259f388ebc061926c3ec860b9edc74` |
| 场景 | 2×5、2×10，各 basic/medium/advanced |
| 来源与批次 | 来源第 1 列，每批 5 块；分别执行 2 批与 4 批 |
| 总预算 | 2×5 1500 步、2×10 3000 步，含标定和主动观察 |
| 原生评分 | 固定提交的原生成功谓词，连续成功要求 5 步 |
| 额外完成指标 | 原生成功且控制器完成释放、撤离、已有成果与稳定自检 |
| 相机与动作 | 原三摄 RGB-D；左臂 8D，右臂初始安全姿态 |
| 策略 | RGB-D 几何视觉、受约束规划与闭环执行，无学习权重 |

这是固定提交上的每批五块研究协议，**不是最新 main 默认网格，也不是其 20 步严格完成模式的成绩**。原生评测器可以使用物体真值评价位置、姿态和稳定性；这些字段只进入独立评估日志，不传回控制器。控制使用真实采集时间、RGB-D、标定、编码器与公开几何，不读取物体真值位姿、实例 ID、接触对象图、原生得分或成功标志决定动作。

原生成功和视觉完成不等价。满数量但稳定性不足仍可能原生失败，原生成功但视觉无法确认也保留为未完整完成；不通过放宽评分、使用评估真值补控制或删掉失败回合提高统计。

## 7. 已知限制与代码导航

剩余失败包括：观察证据不足、整条放置路径不能通过安全/可达性检查、额外夹带或批内几何异常、后续操作扰动旧物，以及终态视觉确认与真实物理稳定不同步。V9 没有全部解决这些问题。R4 的终态确认探索尚未通过既定成功/紧预算对照，未作为本次默认发布。

所有结果限于仿真中的已知盒体和饼干尺寸、公开槽位及规则排列。当前未验证未知盒型、任意散乱抓取、强倾倒、真实深度空洞/反光、硬件延迟或真实接触控制。向实机迁移仍需要相机配准与标定、同步、编码器及夹爪反馈和控制接口验证，仿真得分不是实机成功率。
